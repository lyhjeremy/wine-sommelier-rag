Wine recommendations where every bottle comes from a review

Ask in plain English. A local hybrid retriever finds matching Wine Enthusiast reviews, a cross-encoder reranks them, and Claude recommends two or three, citing each one. If nothing fits, it says so.

What the reranker bought

src/eval.py scores three retrieval setups on twelve requests, each with a written relevance rubric (grape or wine family, country, price cap, descriptor words).

RetrieverP@10MRRnDCG@10
Dense vectors only0.680.880.69
Dense + BM25, fused with RRF0.670.760.68
Dense + BM25 + cross-encoder rerank0.820.920.83

Fusing BM25 in without a reranker lowered MRR, because keyword matches pulled in reviews of the wrong kind of wine. The cross-encoder, which reads the request and each review together, raised precision and nDCG@10 about 21% over the dense baseline.

How a request is answered

  1. The request is embedded locally with all-MiniLM-L6-v2 and searched in Chroma, with any price, country, grape or minimum-score filters applied inside the query.
  2. A BM25 keyword index ranks the same candidates, and Reciprocal Rank Fusion merges the two lists.
  3. The cross-encoder ms-marco-MiniLM-L-6-v2 re-scores the fused shortlist.
  4. Claude gets the top reviews and a system prompt that allows recommendations only from them, each cited by [n].
python -m src.cli ask "elegant and mineral, great with oysters" \
    --country France --max-price 40 --min-points 90

Filters compose with any request. Retrieval runs locally at no cost; generation uses the Claude CLI, or the Anthropic API when ANTHROPIC_API_KEY is set.

Limits

The benchmark is twelve queries with rule-based relevance, so it compares the three retrievers fairly but does not give absolute quality. The default index holds the 30,000 highest-scored reviews of the 129,971 in the dataset, all from one magazine.
